# Приборка без ноутбука: ESP32 + ELM327 (шаг 1)

ESP32 сама опрашивает «Январь» через ELM327 по Bluetooth и раздаёт Wi-Fi. В телефоне открывается та же
страница, что у `python -m vito_diag web` (docs/WEB_PANEL.md). Только чтение.

```
Машина ── ELM327 ~~Bluetooth~~ ESP32 ~~Wi-Fi «vito_diag»~~ телефон: http://192.168.4.1
```

## Прошивка

`tools\flash_esp32_panel.bat` (спросит COM-порт ESP32) или:

```
arduino-cli compile --upload -p COM5 --fqbn "esp32:esp32:esp32:PartitionScheme=huge_app,UploadSpeed=230400" firmware\esp32_obd_panel
```

Скетч: `firmware/esp32_obd_panel/`. Ядро опроса `lada_core.h` — перенос `vito_diag` (K-line ElmLink,
`january.py`, `Poller`) на C++. Тест `tests/test_panel_firmware.py` собирает его на ПК (g++) и гоняет
против того же эмулятора «Января», что и Python: команды адаптеру и итог (блок, ошибки, значения,
подсказки) должны совпадать один в один. `panel_html.h` и `dtc_table.h` генерирует
`python tools/gen_panel_assets.py` из `vito_diag/data/panel.html` и `dtc_ru.json` (тест проверяет,
что не забыли перегенерировать).

## Как пользоваться

1. Вставить ELM327 в разъём, включить зажигание (лучше завести мотор), подать питание на ESP32.
2. ESP32 сама найдёт адаптер по имени (OBD/ELM…) и запомнит адрес. Если адаптеров рядом несколько —
   задать адрес командой `~USE aa:bb:cc:dd:ee:ff` в мониторе порта (115200).
3. Телефон: Wi-Fi **vito_diag**, пароль **vitodiag**. Страница откроется сама («вход в сеть») или по
   адресу http://192.168.4.1.

Служебные команды по USB (115200): `~STATE`, `~SCAN`, `~USE <адрес>`, `~PIN <pin>`, `~FORGET`,
`~WIFI <имя> <пароль>` (после перезагрузки).

## Отличия от версии на ноутбуке

- Нет записи CSV (некуда); история графиков — последние 120 замеров.
- Страница обновляется опросом раз в ~0,7 с (синхронный веб-сервер ESP32), а не потоком.
- Пока только «Январь»; общий OBD-II и CAN (Mercedes) — следующие шаги.
